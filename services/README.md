# Voice Services (STT & TTS)

Два микросервиса для обработки голоса. Реализация полностью соответствует контрактам `docs/contracts/stt.*.json` и `docs/contracts/tts.*.json`.

## Стек
- **STT:** faster-whisper (модель `base`, CPU). Требует ffmpeg.
- **TTS:** edge-tts (голос `ru-RU-SvetlanaNeural`). Требует ffmpeg.
- **Хранилище:** TTS сохраняет аудиофайлы в S3 (RustFS).

## Запуск
Все сервисы (включая базы данных и S3) поднимаются одной командой из корня проекта:
```bash
docker compose up -d --build
```

## Эндпоинты

**POST /v1/transcribe (порт 8010)** - аудио по `audio_url` -> текст:
- `audio_url` принимает только http/https (presigned-ссылки S3).
- Возвращает распознанный текст (до 1000 символов), уверенность и длительность.
- Коды ошибок: 400 (схема), 413 (PAYLOAD_TOO_LARGE), 422 (AUDIO_TOO_LONG, AUDIO_UNREADABLE), 503 (сеть), 504 (дедлайн).

**POST /v1/synthesize (порт 8020)** - текст -> аудио:
- Синтезирует текст, конвертирует в нужный формат и загружает в S3.
- Возвращает `object_key` (путь в бакете `tts`), `duration_ms` и флаг `cached`.
- Ключ кэша детерминирован и учитывает скорость, формат и голос.

## Особенности реализации
- **Валидация:** строгая Pydantic-валидация (`extra="forbid"`), жесткая проверка типов и лимитов.
- **Таймауты:** STT имеет общий дедлайн 25 с. TTS - 20 с (с внутренними лимитами на синтез и конвертацию).
- **Антигаллюцинации:** в STT включен `vad_filter=True` для отсечения тишины и фонового шума.
- **S3-кэширование:** TTS проверяет наличие файлов через `head_object` и хранит длительность в метаданных.
- **Изоляция:** блокирующие вызовы (`ffmpeg`, `ffprobe`, `model.transcribe`, `boto3`) вынесены в `asyncio.to_thread`.
- **Docker:** модели предзагружаются на этапе сборки образа, настроены healthcheck'и с учетом времени загрузки.
